=== 静态版说明（GitHub Pages / 纯静态托管） ===

这个仓库除了本机版（python3 serve.py 8796），还带了一个静态版：
不开服务器、只要静态托管，打开链接就能用界面、存会话、多轮对话。

区别在哪：
  本机版：serve.py 在 127.0.0.1 起 HTTP 服务，浏览器所有 /api/v0/* 都打到它。
  静态版：没有服务器，后端换成 sw.js（Service Worker），在同一个域名下
          接管 /api/v0/* 与 /local/*，真流式 SSE，会话存浏览器 IndexedDB。
          两者对前端完全一样，serve.py 里面的人设、思考卡片、搜索卡片、
          引用角标、文件上传、导出、全文搜索都按原逻辑搬了过来。

访问：
  直接打开站点根地址，第一次进来 Service Worker 落地后会自动接管（不可见）。
  壳子的会话 URL 形如 /a/chat/s/<id>，刷新时由 sw.js 回落 index.html；
  仓库里另有一份 404.html 做双保险。

唯一要注意的：跨域（CORS）
  纯静态站点不能替你做代理，聊天请求是浏览器直接从页面打到模型接口的。
  如果那个接口没返回 Access-Control-Allow-Origin，浏览器会拦掉，
  表现就是气泡里提示"连不上接口：浏览器跨域（CORS）被拦住了"。
  内置网关就属于这种情况（它不吃跨域），所以静态站默认发不出消息。

  两条路解决：
  A. 点左下角齿轮，填一个允许跨域的 OpenAI 兼容接口（URL + Key + 模型），
     大部分自建 one-api / new-api 都允许跨域。
  B. 用仓库 relay/ 里的中转：Cloudflare Worker 免费部署，把上游套在自己的
     域名下并补上跨域头，再把中转地址（结尾带 /v1）填进齿轮。
     具体步骤见 relay/cloudflare-worker.js 顶部注释。

  配好之后立即生效，不用刷新（guard.js 每次发消息都重读本地配置）。

其它：
  - 会话只存在你自己的浏览器（IndexedDB），换设备/清站点数据就没了；
    要备份用 设置 → 数据管理 → 导出所有历史对话。
  - 仓库是公开的话，index.html/sw.js 里那串混淆过的内置网关配置等于公开，
    别人也能拿去用；不想被白嫖就把内置网关从 sw.js 里删掉，只留齿轮手填。
